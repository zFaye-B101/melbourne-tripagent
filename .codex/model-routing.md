# Melbourne TripAgent：项目级模型路由

本文件补充全局 `adaptive-model-router` Skill，不绑定具体模型名称，也不改变全局优先级、动态发现和公告协议。本规则管理开发协作时的模型路由；TripAgent 产品运行时的 LLM 选择、版本、成本和降级策略另行设计，不能自动沿用本规则。

## 动态选型与项目边界

每次新任务和每个重大阶段都重新解析当前账号、目的宿主、工具 schema 实际暴露的模型与推理强度，并建立临时 RuntimeCatalog。官方能力说明只用于分类，不能证明访问权；清单不可核实不等于当前身份不可核实。项目规则不得硬编码型号、日期或替代运行时发现。

- 首版只覆盖 Melbourne CBD 与内城区、1–3 天；远郊和全国城市属于后续范围。
- 数据数量按版本推进：v0 固定 12 条；v0.1 扩展到 30–50 条；v0.2 在质量检查完成后再扩大到 40–80 条。
- v0.1 的 30–50 条扩大到 v0.2 的 40–80 条，必须由 L4 决策确认并记录；L2 实现不得自行扩大数量。
- POI、图片、营业时间、价格和交通事实保留来源、许可证、核验时间与状态；`unknown`/`not_verifiable` 不得计为 Pass。
- LLM 只能解析需求和解释确定性结果，不能创建 POI、改写时间/费用/来源或替代约束检查。

## 项目不变量与工作包契约

每个工作包开始前明确目标/非目标、输入输出与 schema、不变量、假设与未知、验收、失败/恢复、风险和升级条件；L2 实现后报告改动、实际检查、限制、假设和偏离。POI 只收官方开放数据、许可 API 或明确许可图片，并保存 raw、规范化、核验层与字段级来源；证据包括导入统计、去重/冲突/缺失报告和许可记录。

规划器先硬过滤、区域聚类、安排锚点，再填槽、检查和有限修复；结果为 Pass/Fail/Not verifiable，证据为 T01–T10 与计算检查。替换时其他日期冻结，当天其他 POI 身份默认冻结；可为插入替代项重算可移动后续时刻，但不可移动预约锚点。无解时原行程保持不变，不产生半更新；撤销恢复替换前目标日期快照。证据包括前后 diff、锚点不变、无解和撤销测试。

UI 覆盖初始、解析失败、生成中、部分未知、无解、替换中、图片失败和系统错误。TripRequest 缺少天数必须询问。LLM 只读写允许字段，推荐理由只能引用用户偏好和已有 POI 字段；用 schema 校验、越权字段测试和失败降级记录证明边界。产品运行时 LLM 的选择、版本、成本和降级策略仍是单独设计，不由本文件自动改变。

## 升级、降级与交付状态

改变 Melbourne 范围、版本数量、数据许可、schema、规划不变量、LLM 字段白名单、替换冻结语义、密钥/隐私或公开部署时，重新评为 L4；若涉及冲突、公开发布、安全、隐私或不可逆外部影响则评为 L5。两次有意义修复失败、固定测试暴露契约级问题或出现未授权范围也升级。只有接口、验收与恢复方式冻结后才降级。C4/R5/R6 的全局双锁仍分别适用；L6 永不默认，纯分析不凭空要求授权。

区分 `designed`、`implemented`、`smoke_tested`、`data_verified`、`demo_ready`、`deployed`，证据来自实际运行和保存记录，不填写推测数字。公告遵循全局计划→成功/失败协议，并包含任务等级、实际型号、实际 effort、受限降级和保持不变信息。
