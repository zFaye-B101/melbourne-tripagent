# 15. v0.4.2 Agent-first 本地实现契约

## 1. 目标与范围

本轮把自然语言重新确立为旅行助手的主入口，并将密集设置收纳为辅助修正。只修改和验证本地版本，不调用 WorkBuddy／Sites hosting，不覆盖线上 v0.3。

当前没有真实 LLM、NLU API、BFF 或 API Key。界面中的 `Agent` 表示交互角色；实际需求理解由可测试的本地规则完成，并持续显示 `基础理解模式`。

## 2. 两阶段生成契约

```text
idle
  → interpreting
  → needs_clarification | error | awaiting_confirmation
  awaiting_confirmation --用户确认当前提案→ planning → plan_ready
  awaiting_confirmation --任一条件改变→ 提案过期 → interpreting
  plan_ready --新请求失败→ 旧计划和替换历史保持不变
```

1. 自然语言、精细设置和热门卡共同生成请求指纹。
2. `buildPlanProposal()` 只复制已校验请求并生成可读摘要，不调用规划器。
3. 摘要逐项标注 `你说的／手动调整／Agent 默认／需确认`。
4. 缺少天数时只追问 1–3 天；范围错误、冲突或未知起点直接说明。
5. 用户修改任一条件后，`isProposalCurrent()` 必须拒绝旧确认。
6. `planTrip()` 只在用户点击 `按这些生成行程` 后执行。
7. WebMCP 工具只允许准备待确认提案，不能绕过确认门。

## 3. 首屏与设置层级

首屏顺序固定为：

1. 自然语言输入；
2. 发送与精细调整；
3. 横向示例语句；
4. 待确认理解卡；
5. 尚未生成时的精选景点轮播；
6. 生成后的概览、提醒、Day 切换与当前日程。

精细设置只分三组：

- `行程边界`：天数、出发时间、日期、起点、活动范围；
- `同行人与费用`：成人、优惠、儿童、亲子、少走路、预算、PTV 支付方式；
- `游玩偏好`：节奏、五档场所环境、八类游客体验。

起点默认使用 Melbourne CBD 的 Flinders Street Station 代理坐标并明确显示。可识别 CBD、Southbank、Docklands、Carlton、East Melbourne 与当前 40 POI；未知酒店或地址不得静默回退。

## 4. 分类与证据边界

City of Melbourne Open Data 的 `theme/sub_theme` 作为原始官方分类保留在来源详情中。页面上的八类体验是 TripAgent 面向游客整理的产品标签：

- 博物馆与展览；
- 历史与遗产；
- 公园与花园；
- 河畔与城市漫步；
- 城市地标与观景；
- 表演与音乐；
- 体育场馆；
- 市集与本地生活。

设置中显示每类在当前 40 POI 的覆盖数，低覆盖主题明确标记。咖啡、餐厅和夜生活当前覆盖不足，只给出未处理提醒，不假装已用于排序。

推荐依据只允许使用结构化偏好与 POI 已有字段。界面可显示 `历史与遗产／偏户外／亲子友好／邻近` 等短标签，不显示未由真实路线或反事实证明的因果理由。

## 5. 必须保留的既有行为

- 10 张本地授权图片的精选卡可拖动、键盘访问或使用图片外的箭头浏览；无自动轮播和暂停键。
- 每张卡维持 `默认／必去／避开` 三态，且进入同一请求指纹。
- 每天有午餐后活动，晚出发请求仍按用户时间起步。
- Day 标签一次显示一天，地图默认关闭，地点短说明默认可见。
- 替代地点弹窗列出全部可行与不可行候选；确认前不修改结果。
- 原子替换、其他日期冻结、失败不提交和最多 20 步 LIFO 撤销保持不变。
- 票价、PTV 与未知费用继续按离线核验快照披露，不扩展成实时结论。

## 6. 验收与后续边界

自动验收至少覆盖：

- `出发点CBD`、`从CBD出发`、五个命名区域和未知酒店；
- 五档场所环境、八类体验及各自来源；
- 提案生成、默认值披露、缺天数澄清和请求指纹失效；
- 原规划器、替换、撤销、费用、数据导入、类型、静态检查和生产构建回归。

真实 LLM 接入属于独立 `v0.5 NLU` 工作包：必须使用服务端 Provider Adapter、供应商无关 Schema、语义守卫、超时与整次规则回退；需要再次批准外部请求、密钥和部署。Australia 多城市扩展继续等待 Melbourne 本地版本稳定。
