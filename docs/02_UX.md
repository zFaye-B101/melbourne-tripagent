# 02. UX 与页面结构

## 1. 信息架构

首版采用一个单页规划器（Single-page Planner），完成“输入 → 生成 → 检查 → 调整”，不拆成复杂多页面产品。

```text
品牌栏
  ↓
自然语言需求输入 + 示例语句
  ↓
需求理解卡（字段值 + 来源）
  ↓ 用户确认
确定性规划器
  ↓
未生成时：10 张热门景点卡片横向轮播
  ↓
行程概览
  ↓
出发提醒
  ↓
吸顶 Day 切换
  ↓
当前 Day 的完整行程
  ↓
折叠的规划说明与数据来源
```

## 2. 页面区块

### A. 顶部栏

- `Melbourne TripAgent`
- 副标题：`墨尔本 1–3 天行程试做版`
- 状态标签：`40 个地点 · 来源可查`

不展示模型名称或“LLM 已接入”，因为当前版本仍是基础规则理解模式。

### B. 需求输入卡片

- 提示：`想怎么逛墨尔本？`
- 辅助说明：`有什么旅行偏好？行程天数（1–3 天）、同行人数和住宿区域，也可以一起写下来。`
- 大尺寸多行输入框是首屏主入口，示例语句位于输入框下方，点击只填入、不自动提交。
- 主按钮：`整理我的需求`。当前实际执行的是本地基础规则，因此同时显示 `基础理解模式`，不声称已调用真实 LLM。
- `详细设置` 是修正入口，而不是与自然语言竞争的第二套首页表单；内部只分三组：
  - `时间与范围`：天数、每日出发时间、日期、住宿或起点、活动范围；
  - `同行人和预算`：成人、优惠票人数、儿童年龄、亲子、少走路、整趟预算、公共交通刷卡方式；
  - `游玩偏好`：节奏、五档场所环境倾向、八类游客体验。
- 场所环境采用 `室内为主／偏室内／均衡／偏户外／户外为主` 五档分段选择；活动范围采用 `CBD 集中／市中心优先／市区及内城` 三张说明卡，不伪装成精确百分比。
- 八类体验是本项目面向游客整理的选择分类；页面同时显示当前 40 POI 的覆盖数量，并明确它们不是 City of Melbourne 的官方旅游分类。

推荐示例：

1. 墨尔本玩 2 天，住 CBD，轻松一点，喜欢历史和花园。
2. 带孩子玩 1 天，下雨也能去，想看博物馆和展览。
3. 墨尔本 3 天，主要在市内，喜欢室外，从 CBD 出发，每天 11 点出门。
4. 玩 2 天，少走路，必去 Melbourne Skydeck，避开水族馆。

### C. 需求理解卡与热门景点

发送需求后先显示 `也许你想……`，不立即生成行程。基础七项收在一个共享面板中：桌面端为两排，移动端为最多四排；额外偏好另起紧凑分组，不截断。每个字段必须标注为：

- `描述中提到`：能够从原文找到证据；
- `详细设置`：来自用户明确选择；
- `暂用默认`：系统假设；
- `需要补充`：缺少天数等阻断字段。

当旅行描述与详细设置不一致时，页面逐条列出冲突。每条冲突都可直接打开详细设置并定位到对应控件；用户也可回到原始输入框自行修改描述。系统不会静默决定保留哪一侧。

用户修改原文、设置或热门卡后，旧理解立即过期，必须重新发送；只有当前理解可以通过 `按这些生成行程` 调用规划器。缺少天数时只追问 1 个问题。

未生成行程时展示 10 张本地真实图片的精选景点卡。用户可在每张卡上互斥选择 `默认／必去／避开`；卡片支持拖动、键盘和图片外的上一组／下一组按钮，不自动轮播，也没有暂停键。精选轮播仍固定为 10 个地点，但完整图片库覆盖规划器的全部 40 个地点，供逐日行程和替换列表共用。

成功生成后的概览集中展示：

- `2 天`
- 地点数量和地点间估算距离
- 兴趣标签，例如 `艺术／历史`
- 节奏、少走路、雨天室内、亲子和避开拥挤等偏好
- 必去和已避开的已知 POI
- 日期；未指定时明确写 `未指定`
- 每日离开起点的时间、CBD 代理起点说明和区域范围
- 已核实部分的景点门票、公共交通最高预留与未知费用数量

缺失日期时显示：

> 未提供具体日期，营业时间和临时关闭信息需要出发前确认。

### D. 出发提醒

默认只展示需要用户留意的事项，不把内部检查状态直接暴露给普通用户：

- `已安排好`：确定性检查已经通过。
- `需要调整`：硬约束无法满足，不能继续生成。
- `与偏好有差距`：软偏好未完全满足，但仍可使用。
- `出发前确认`：营业时间、票价、实时交通、拥挤和无障碍等动态信息未知。

所有检查结果仍保留在折叠的 `规划说明与数据来源` 中，便于复核。

### E. Day 导航

- `Day 1`、`Day 2`、`Day 3`
- 导航吸顶，点击后切换当前完整日程；不在同一页面堆叠全部日期
- 当日主题，例如 `艺术花园线`

所有 Day 使用同一品牌色，当前日期高亮即可。

### F. 当日卡片

示例：

> 09:30 开始 · 15:58 结束 · 3 个地点 · 地点间约 1.0 km

不能只写含义不明的“交通 15 km”。

每日地图默认折叠为 `查看当天地点位置示意`，展开后显示坐标连线，并持续标注 `不是导航路线`。

### G. POI 时间线卡片

每个地点展示：

- 到达和离开时间
- 官方英文名，可附中文名称
- 类别和区域
- 推荐理由，默认 1–2 行
- 建议停留时间
- 来源和最近核验日期入口
- 地点实景照片；尚无已核验照片时显示清楚标注的类别示意
- 文本按钮 `换一个`

连接段示例：

> 步行约 8 分钟 · 600 m  
> 电车约 12 分钟 · 含候车缓冲 · 估算

### H. 替换反馈

- 替换后说明：`已将“地点 A”替换为“地点 B”。`
- 自动重算当天距离、交通与后续时间。
- 顶部概览和底部反馈条都提供 `撤销`，最多保存 20 步。
- 无候选时不修改原行程，说明需要放宽的条件。
- 点击 `换一个` 先打开包含全部可行候选的对话框；取消不修改，单选并确认后才原子替换。

## 3. 桌面端布局

```text
┌────────────────────────────────────────────┐
│ 顶部栏                                     │
├────────────────────────────────────────────┤
│ 自然语言输入／示例／整理／详细设置         │
├────────────────────────────────────────────┤
│ 也许你想……／紧凑来源摘要／确认生成         │
├────────────────────────────────────────────┤
│ 未生成：精选景点轮播                       │
├────────────────────────────────────────────┤
│ 已生成：概览／出发提醒                     │
├────────────────────────────────────────────┤
│ Sticky: Day 1   Day 2   Day 3              │
├────────────────────────────────────────────┤
│ 当前 Day 卡片（折叠地图 + 紧凑时间线）     │
├────────────────────────────────────────────┤
│ 折叠：规划说明与数据来源                   │
└────────────────────────────────────────────┘
```

页面整体纵向滚动，不让地图和时间线分别出现两个滚动条。Day 切换只改变当前日程，不丢失替换与撤销状态。

## 4. 移动端布局

- 自然语言输入优先，精细设置使用右侧抽屉，避免首页堆叠长表单。
- 示例需求使用横向滑动标签或小尺寸自动换行。
- 整理按钮与详细设置按钮保持清晰主次，小屏时整理按钮占据主要宽度。
- Day 导航吸顶。
- 默认优先显示时间线，地图按天折叠。
- POI 使用紧凑缩略图；有核验照片时显示实景图，否则显示清楚标注的地点示意。
- 来源、许可证和完整检查记录放在原生折叠区中。

## 5. 交互状态

| 状态 | 页面行为 |
|---|---|
| 初始 | 显示自然语言输入与精选景点，不渲染空地图和空结果框 |
| 已理解待确认 | 显示结构化条件、来源与默认值，不调用规划器 |
| 理解已过期 | 标记“新条件尚未应用”，禁止使用旧确认生成 |
| 解析失败 | 标出无法理解的部分并保留原文 |
| 缺少天数 | 在输入框下询问，不猜测 |
| 生成中 | 禁止重复提交；使用已经确认的结构化条件调用确定性规划器 |
| 部分数据未知 | 继续生成，在具体字段旁标记待确认 |
| 成功 | 替换结果后自动定位到总览，默认选中 Day 1；新请求失败时保留上一份成功结果 |
| 无可行方案 | 展示冲突原因和可放宽条件 |
| 替换中 | 只锁定目标卡片，其他内容不闪烁或重置 |
| 图片失败 | 使用类别占位图 |
| 系统错误 | 保留输入并允许重试，不暴露内部错误栈 |

## 6. 文案原则

- 用 `预计`、`估算`、`待确认` 表达数据边界。
- 不用 `完美行程`、`100% 可行` 等绝对表述。
- 技术状态转成用户状态，例如把“约束求解失败”写成“当前预算和必去地点无法同时满足”。
