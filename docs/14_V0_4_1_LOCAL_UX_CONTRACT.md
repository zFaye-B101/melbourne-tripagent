# 14. v0.4.1 本地体验修订契约

> 历史记录：v0.4.2 已用自然语言主入口和 Agent 提案确认流程覆盖本文件中的“快速设置为主要入口”规则；其余关于紧凑 Day、替代地点、来源披露和本地不发布的边界继续有效。当前契约见 `15_V0_4_2_AGENT_FIRST_CONTRACT.md`。

## 范围

本轮只更新本地源码与本地静态构建，不调用 WorkBuddy／Sites hosting，不覆盖线上版本。

## 已冻结的产品规则

- 快速设置是主要入口；自然语言改为“一句话补充（可选）”，并明确只在本机做受限关键词识别。
- 首屏顺序固定为：快速设置 → 单行一键示例 → 可选文字补充与生成 → 热门景点。
- 热门景点仅手动浏览，不自动轮播；上一组／下一组按钮位于卡片图片之外。
- 逐日安排一次只显示一天，Day 标签用于切换，不再把全部日期纵向堆叠。
- 景点短说明默认可见；来源与核验信息继续折叠。
- 必去状态使用高对比实心徽章，且必去地点不提供替换操作。
- 推荐依据只允许使用可验证标签：分类偏好、室内／户外、中央城区、亲子友好、少走路友好。没有证据时不显示理由。
- 删除“与当天地点同区，减少折返”和“补足全天时段”等未被实际路线或反事实证明的因果文案。
- 路程显示交通方式、估算分钟和直线距离；1.2 km 以内可标“邻近”，但仍保留数值与直线估算语义。
- “查看替代地点”审计当前数据集除目标外的全部地点；可行候选和暂不可选候选均可查看，每个不可选地点只有一个首要原因。
- 替换仍须确认后才提交；失败保持原行程，其他日期与当天非目标地点不变，撤销语义不变。

## 解析边界

- 空文字配合已选择的天数可以生成行程。
- 否定兴趣不会被标为正向偏好。
- 只有“必去／必须／一定要去”等明确措辞才产生必去硬约束；“想去”不自动升级为必去。
- 不接入 LLM、外部 NLU、实时路线、天气、营业时间或客流。

## 桌面密度目标

- 快速规划默认折叠态保持紧凑，让热门景点标题和首张卡片照片尽可能在常见首屏中可见。
- Day 地图默认关闭，时间无冲突状态移入标题栏，交通卡改为左栏紧凑文本，地点行内边距压缩。
- 默认折叠时以常见桌面视口完整查看单个 Day 为目标；移动端、200% 缩放、展开地图或来源后允许正常纵向滚动，不裁切内容、不使用 Day 内部滚动。

## 模型路由记录

- 产品、证据与替换语义：L4，`gpt-5.6-sol / ultra`，只读设计复核。
- 代码现状与回归风险：L2，`gpt-5.6-luna / medium`，只读审计。
- 站点实现：由 Site owner 主会话完成；运行时无法验证主会话精确型号，因此按通用路由规则保持现有模型，不虚构型号切换。

## 验收边界

- 自动检查覆盖规划器、数据导入、类型、代码规范和静态构建。
- 本轮未执行浏览器视觉截图验收，也未执行任何线上发布；布局观感由本地 `http://localhost:3000/` 继续检查。
