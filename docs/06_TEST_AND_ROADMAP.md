# 06. 测试、完成定义与路线图

## 1. 固定测试需求

至少使用以下场景，不以主观“AI 看起来不错”代替验收：

| ID | 输入重点 | 预期关注 |
|---|---|---|
| T01 | CBD 一日、低预算 | 免费地点、路线紧凑、费用未知处理 |
| T02 | 两日、艺术 + 咖啡、公共交通 | 跨天去重、主题分配、交通估算 |
| T03 | 带长辈、少走路、频繁休息 | 活动数量、步行限制、缓冲时间 |
| T04 | 雨天亲子、室内优先 | 室内筛选与未知天气边界 |
| T05 | 三日、一个必去和一个避开 | 硬约束处理 |
| T06 | 没有日期和预算 | Not verifiable，而不是自动通过 |
| T07 | 周一请求可能闭馆的场所 | 有日期时的开放检查 |
| T08 | 轮椅需求 | 缺少无障碍事实时不做保证 |
| T09 | Great Ocean Road + 仅市区 | 明确提示超出范围 |
| T10 | 极低预算或互相冲突的要求 | 返回无可行方案与最小放宽建议 |

## 2. 自动检查

每次生成都应检查：

- `days.length` 与用户天数一致。
- 所有 `poi_id` 存在于当前 POI 快照。
- 同一天时间段不重叠。
- 跨天重复数量为 0。
- 必去和避开约束得到正确处理。
- 每天活动位于用户允许时间窗内。
- 只有费用字段覆盖完整时预算才可以为 Pass。
- 只有拥有日期化开放信息时开放状态才可以为 Pass。
- 地图标记序号与时间线顺序一致。
- 仅有坐标连线时显示“示意路线”。

Agent-first 交互还必须检查：

- 需求提案只做解析和摘要，确认前不调用规划器。
- 每项摘要区分原文、手动调整、默认值与待确认字段。
- 原文、精细设置或热门卡改变后，旧提案失效。
- 缺少天数时只追问天数；未知起点或字段冲突不静默修正。
- `从CBD出发`、`出发点CBD` 与五个命名区域在无空格表达下也能正确解析。
- 页面 WebMCP 工具只准备提案，不能跳过确认门。
- 新请求解析或规划失败时，上一份成功行程与替换历史保持不变。

## 3. 替换测试

- 目标 POI 确实变化。
- 其他日期完全不变。
- 替换后无重复。
- 前后交通、当天时间和汇总重新计算。
- 超预算或时间冲突候选被拒绝。
- 无可行候选时保留原行程并解释原因。
- 撤销后恢复原日期快照。

## 4. 数据测试

- 同一地点存在多个名称和来源时能够去重。
- 两个来源的动态字段冲突时进入 `conflicted`。
- 坐标缺失或超出范围时不进入规划器。
- 图片缺少作者或许可证时使用占位图。
- 过期动态字段标记为 `stale`。
- `free`、价格区间和未知价格不会混为一谈。

## 5. 故障与降级测试

- LLM/API 失败时页面不崩溃并保留用户输入。
- LLM 输出非法 JSON、额外字段或缺少证据时拒绝结果，最多修复重试一次。
- LLM 超时后整次切换到规则解析，不能把两套解析结果拼接。
- 提示注入文字只能作为旅行原文处理，不能改变 Schema、白名单或系统规则。
- 外地城市、四天、未知地点、轮椅和预算等未支持硬约束不能被降级路径静默绕过。
- 进入规划器的所有 POI ID 必须属于当前数据快照。
- 图片失败时继续显示地点卡片。
- 路由不可用时切换为明确标注的估算。
- 候选不足时返回原因，不重复或虚构 POI。
- 替换失败时不产生半更新状态。

## 6. 阶段计划

### v0：交互闭环（已完成）

- 12 条有来源的测试 POI。
- 单页输入、解析摘要、Day 导航、地图标记和时间线。
- 规则生成、三态检查、“换一个”和撤销。
- 不接真实 LLM，先用固定结构验证业务逻辑。

完成证据和测试数量以当时实际命令输出为准；本轮扩量后需重新运行完整命令集。

### v0.1：真实数据（40 条首批快照已完成）

- 从 City of Melbourne Open Data 242 行快照中选择 40 条 POI。
- 完成 manifest、normalized、verified 和 planner adapter 四层导入。
- 本阶段不补充实时数据，不接 Australia 多城市，也不部署公网。
- OSM/Overpass 字段与 Commons 合规图片作为未来可选增强，不属于本阶段 core POI 导入。

完成门槛：每条展示 POI 有来源；去重、冲突和缺失报告可查看。

### v0.2：静态发布基线（已完成）

- 完成 40 POI、生产构建与 WorkBuddy 静态部署。
- 公开链接保持为 <https://melbourne-tripagent.app.workbuddy.host/>。
- 中国境内普通网络验收仍待验收人员完成。

### v0.3：纵向 UX 与 LLM 契约（已发布的线上版本）

- 初始页只显示输入；结果按概览、出发提醒、每日行程和折叠说明纵向排列。
- Day 导航只滚动定位，不隐藏其他日期；地图按天折叠。
- 用户文案不再直接暴露 `Pass / Fail / Not verifiable`。
- 冻结供应商无关的 `TripRequestDraft v1`、证据要求、POI 白名单和降级规则。
- 当前仍不调用真实 LLM，也不在 WorkBuddy 静态页面中放置 API Key。

### v0.4-local：热门卡、时间修复与费用（本地已完成）

- 初始页加入 10 张本地授权图片的热门景点卡与 `默认／必去／避开` 三态。
- 加入天数、11:00 等每日开始时间、CBD 代理起点、中央城区和户外偏好的结构化解析。
- 修复午餐后空白：各节奏都有每日地点数、下午活动和结束覆盖阈值。
- 加入 40 条门票快照、PTV 有效期快照、参考预算和未知费用披露。
- `换一个` 改为全量候选对话框，确认后才原子替换。
- 当前只在本地实现和验证；未覆盖 WorkBuddy 线上 v0.3。

完成证据见 `13_V0_4_LOCAL_VALIDATION.md`。

### v0.4.1-local：紧凑信息层级与替代地点审计（本地已完成）

- 热门卡改为仅手动轮播，移除自动轮播和暂停键，箭头位于图片外。
- Day 标签一次只显示一天；地点短说明默认可见，来源继续折叠。
- 推荐依据改为可验证短标签；替代地点弹窗展示全部可行与不可行候选。

历史契约见 `14_V0_4_1_LOCAL_UX_CONTRACT.md`。

### v0.4.2-local：Agent-first 本地交互（本地已完成）

- 自然语言恢复为首屏主入口，精细设置降为三组辅助修正。
- 加入 `理解 → 核对来源与默认值 → 用户确认 → 确定性规划` 两阶段流程。
- 加入提案指纹与过期确认守卫；WebMCP 同样不能绕过确认。
- 支持五档场所环境、八类游客体验和五个命名区域起点；产品分类与官方原始分类明确区分。
- 当前仍是本地规则理解，无真实 LLM、API Key 或 BFF；本版本未发布。

实现契约见 `15_V0_4_2_AGENT_FIRST_CONTRACT.md`；自动测试数量以最新实现日志的实际命令输出为准。

### v0.5：联网 NLU 实验（计划，需另行批准）

- 通过服务端 Provider Adapter 接入实验模型，不把 API Key 放进静态前端。
- 固定 `TripRequestDraft v2`、语义守卫、超时／429／非法输出回退和中国网络验收矩阵。
- LLM 仅提取结构化需求，不生成 POI、票价、路线或约束结论。

### v0.5：演示材料（计划）

- README、架构图、测试报告和演示录屏。
- 完成中国境内普通网络验收。

### v1：扩展评估

- Greater Melbourne / Victoria。
- 真实路由和天气。
- ATDW 许可、费用和密钥方案评估。
- Australia 多城市的数据隔离与城市级配置。

## 7. 完成定义

以下状态必须分开记录：

1. `designed`：方案和 schema 已完成。
2. `implemented`：代码存在，但不代表可用。
3. `smoke_tested`：最小闭环实际运行。
4. `data_verified`：POI 来源和准入检查通过。
5. `demo_ready`：固定测试和演示材料完成。
6. `deployed`：公网地址实际可访问。

截至 2026-09-15，线上 v0.3 已达到 `deployed`，但未完成中国境内网络验收；v0.4.2-local 已达到 `implemented`、`smoke_tested` 与 `data_verified`，尚未发布。真实 LLM、实时数据和 Australia 扩展仍未完成。

## 8. 实施日志要求

每次迭代记录：

- 日期、目标和实际完成项。
- AI 生成或修改了什么。
- 作者做了哪些取舍、核验和测试。
- 使用的数据快照和提示词版本。
- 失败、修复和剩余限制。
- 可复现命令或操作路径。

这些记录将成为之后写简历和回答追问的证据。
