# 01. Product Requirements Document

## 1. 产品定义

**产品名：** Melbourne TripAgent  
**一句话定位：** 用自然语言生成有来源、可检查、可局部调整的墨尔本短途行程。  
**首版语言：** 中文界面；POI 保留官方英文名称，可附中文说明。  
**首版范围：** Melbourne CBD 与内城区，1–3 天，不包含 Great Ocean Road、Phillip Island 等远郊一日游，也不扩展到其他澳大利亚城市。

## 2. 问题与机会

普通大模型能够写一份看似合理的旅行攻略，但容易出现以下问题：

- 编造不存在或已经关闭的地点。
- 不了解真实坐标，导致路线来回折返。
- 忽略营业时间、停留时间、用餐和交通缓冲。
- 修改一个景点时重写整份行程，破坏用户已经接受的安排。
- 给出“实时票价”“当前开放”等没有数据来源的结论。

本项目不是追求覆盖所有旅游服务，而是让一份短途行程具备基本的事实来源、约束一致性和可调整性。

## 3. 目标用户

### 主要用户

- 第一次到墨尔本、停留 1–3 天的中文旅行者。
- 住在 CBD 或内城区，以步行和公共交通为主。
- 希望表达“喜欢咖啡和艺术”“带长辈少走路”等自然语言偏好。

### 暂不覆盖

- 需要实时订票、酒店和航班管理的用户。
- 复杂自驾、多城市或跨州长途路线。
- 需要保证实时交通、排队和库存的商业旅行服务。

## 4. 用户输入

用户可以输入自然语言，系统应识别：

| 字段 | 必需 | 缺失处理 |
|---|---:|---|
| 天数 | 是 | 直接询问，不自行猜测 |
| 日期 | 否 | 允许生成，但动态开放状态标记为待确认 |
| 住宿或起点 | 否 | 默认 Flinders Street Station，并明确显示假设 |
| 人数 | 否 | 默认 1 人 |
| 总预算 | 否 | 费用只做分项估算，不判断是否超预算 |
| 交通方式 | 否 | 默认步行 + 公共交通 |
| 兴趣 | 否 | 默认经典首次到访路线 |
| 行程节奏 | 否 | 默认适中 |
| 必去／避开 | 否 | 作为硬约束处理 |
| 饮食／无障碍 | 否 | 只有数据支持时才做保证 |
| 天气偏好 | 否 | 可接受“雨天室内优先”，首版不接实时天气 |

## 5. P0 功能

1. 自然语言输入与 3–4 条示例需求。
2. 把需求解析为可编辑的结构化标签。
3. 从本地 POI 库召回候选地点，不允许 LLM 发明 POI。
4. 生成 1–3 天时间线，每天安排 3–5 个主要活动。
5. 展示 Day 导航、当日主题、费用、步行强度、地点卡片和来源状态。
6. 使用地图显示各日 POI 标记；路线和交通数据不可靠时必须标记为估算。
7. 检查重复、时间重叠、范围、预算、开放状态和未核实动态信息。
8. 支持“换一个”：仅重新规划目标地点及其前后交通。
9. 支持一次撤销替换。
10. 覆盖加载、错误、无可行方案、图片缺失和部分数据未核实状态。

## 6. P1 功能

- 独立 LLM API 接入和更自然的追问。
- 真实步行或驾车路由服务。
- 保存与恢复最近一次行程。
- 生成可分享链接或导出图片。
- 实时天气与雨天自动替代。
- 扩展到 Greater Melbourne 和 Victoria。

## 7. 明确非目标

- 用户系统、社交、评论和后台运营平台。
- 酒店、航班、餐厅或门票预订。
- 支付、库存、动态票价保证。
- 实时公共交通和拥堵预测。
- “落地率 100%”等不可解释的 AI 分数。
- 第一版全国城市切换。

## 8. 输出内容

每份行程至少包含：

- 已识别需求、缺失信息和系统假设。
- 每日主题、开始／结束时间、预计费用和步行强度。
- 每个 POI 的时间段、名称、类别、区域、图片、建议停留时间和推荐理由。
- POI 之间的交通方式、距离／时间及“估算”标记。
- 营业时间、价格等动态信息的核验状态和来源入口。
- 跨天重复、硬约束冲突和未核实字段的检查结果。

## 9. 成功标准

以下是验收目标，不是当前已经实现的指标：

- 展示的 POI 100% 来自本地数据且有来源记录。
- 硬约束违规为 0；无法满足时返回原因，不硬凑行程。
- 跨天重复 POI 为 0。
- 时间线无重叠，预算与结束时间可以重新计算。
- 未核实动态字段披露率为 100%。
- “换一个”只影响目标日期，并且可以撤销。
- 六类代表性旅行需求均获得可理解的结果或明确失败原因。

## 10. 产品原则

- **先真实，再好看。** 无来源的数据不进入最终行程。
- **先确定性，再生成式。** 事实和计算不交给 LLM 决定。
- **允许未知，不允许假装知道。** 缺失字段显示“待确认”。
- **局部修改优先。** 用户确认过的其他日期和地点默认冻结。
- **首版可解释。** 每一个状态和失败原因都能在面试中说明。
