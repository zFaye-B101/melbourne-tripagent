# 可复用 LLM 接入组件：本地第二至四阶段

## 本阶段边界

独立包位于项目同级的 `../llm-gateway-kit/`。它不导入 TripAgent 的景点、行程、提示词或数据版本；内置 OpenAI Responses 与百炼兼容接口两条服务端调用路径，并允许服务端注册自己的结构化任务。包默认不调用模型。非旅游的客服文本分类及百炼传输测试均使用模拟响应，不需要真实 API Key。

TripAgent 已将 `site/bff/provider-openai.ts` 和 `site/bff/provider-dashscope.ts` 的供应商通信改为引用该包，仍保持原有 `/v1/trip-requests/parse` 接口、旅行提示词和 Draft v2、证据/语义校验及本地规则回退。百炼的 `qwen3.8-flash` 固定模型、免费额度确认、订阅型 Key 拒绝、跨请求熔断，以及仅限本机回环地址使用的门禁均留在 TripAgent；独立包只识别额度错误并通知调用方，不替调用方控制费用。DeepSeek 和智谱适配器尚未迁移。

## 在未来 WorkBuddy 项目中的接法

WorkBuddy 发布静态页面；每个项目另设服务端 BFF（backend-for-frontend）。静态页面只调用该 BFF，不能携带 API Key。BFF 从服务端配置模型与密钥，注册该项目自己的任务定义，并在调用前完成用户同意、服务端决定的配额主体、限流与费用控制；调用后独立核验业务事实与回退。较大范围公开服务宜加入身份或抗滥用验证；本次小范围匿名演示拟使用服务端固定的共享预算主体，不要求邀请码，但可能被他人耗尽共享额度。

第三阶段在独立包的 `llm-gateway-kit/http` 入口新增了默认关闭的 HTTP 请求处理器模板。它固定服务端任务，只接收文本与本次同意标记；只有部署方实现调用者策略、限流、原子预算预留及结算四个钩子，且配置明确的来源和费用上界时，才会调用模型。调用者策略可使用已验证的身份，也可为受严格全局预算保护的小范围匿名演示提供服务端固定的共享主体；后者不是身份核验。模板仍不是可直接公开的 BFF：不提供托管、真实用户体系或已证明的供应商费用上限。具体边界见独立包的 `README.md` 和 `SECURITY.md`。TripAgent 当前 BFF 没有切换到这个模板，现有线上行为没有因此改变。

第四阶段先收紧 TripAgent 现有 BFF 的公开模型入口：非本机回环请求即使带有 `LLM_ENABLED=true`、供应商配置和限流绑定，也不会调用模型，继续采用规则理解。本机模拟及受控试验流程保留。这个防误开门槛不是身份验证或预算实现；当前 Parse API 的请求/响应契约也不同于通用 HTTP 模板，尚不能直接替换。此阶段没有连接真实 API 或发布。

随后本机阶段为 TripAgent BFF 接入了可选的共享预算通路，并在无密钥的隔离运行器验证超额拒绝与重启后的持久拒绝；公网硬门槛依旧关闭。只有云端预算、限流、供应商实际成本上界、隐私与目标地区验收完成后，才可显式重新审查公网门槛。详见 [本机预算验收](28_LOCAL_SHARED_BUDGET_SMOKE.md) 与 [发布门槛](25_ONLINE_LLM_RELEASE_GATE.md)。

本地 `site/package.json` 通过 `file:../../llm-gateway-kit` 引用独立包。将来迁移到另一台机器或仓库时，需让包有独立的版本化来源，并在安装阶段提供它；只复制 `site/` 目录无法完成后端构建。

## 放行条件与未完成项

- 第二、三阶段只使用模拟模型响应；没有调用真实供应商、打开线上 LLM 或部署 WorkBuddy。
- 包内提供 OpenAI Responses 与百炼兼容接口适配器；DeepSeek、智谱仍由 TripAgent 自身处理。若未来项目要共用这两家，需要逐个抽取并做各自的离线回归。
- 百炼的免费额度确认标记只是本地配置，不证明控制台当下仍有额度或“用完即停”仍开启，不能据此允许公开调用。
- `jsonSchema` 是模型输出约束；每个任务仍必须提供服务端 `validateOutput`，并独立核验业务事实。模型返回 JSON 不等于结果正确。
- 公开使用还须满足 [线上 LLM 发布门槛](25_ONLINE_LLM_RELEASE_GATE.md)，包括服务端决定的配额主体、总体限流、费用硬上限、供应商隐私条款和真实网络验收；本次小范围演示不设登录或邀请码。

## 本地验收

从 `site/` 执行 `npm test` 会运行 TripAgent 测试、POI 导入测试和独立包测试。另需通过 `npm run typecheck`、`npm run lint`、`npm run build`、`npm run release:validate` 和 BFF Worker 的 `wrangler deploy --dry-run`。只有实际部署且验收线上请求后，才能标记为已上线；本文件只记录本地阶段。
