# v0.4.3 景点视觉、冲突定位与中文文案契约

日期：2026-09-15  
范围：仅修改本地版本，不更新 WorkBuddy 线上站点。

## 1. 景点视觉

- 行程时间线和“查看替代地点”中的每一个地点都必须在名称旁显示视觉素材。
- 当前只有 10 个地点拥有作者、许可、来源页和本地文件均已核验的实景照片；这些地点显示真实照片并在来源区披露署名。
- 其余 30 个地点不借用其他景点或城市天际线冒充实景，统一显示与类别对应的本地点位示意，并明确标注“地点示意”。
- 图片加载失败时自动降级为同一类别示意，不影响排程、替换和撤销。
- 图片只增强浏览体验，不参与地点事实、门票、位置或排序判断。

## 2. 描述与详细设置冲突

- 自然语言仍是主要入口，详细设置只用于补充或修正。
- 当同一个条件在旅行描述和详细设置中不一致时，不静默覆盖，也不生成新行程。
- 冲突信息必须包含机器可读的字段目标：天数、每日出发时间、每天起点、主要活动区域、室内外偏好、节奏、体验偏好、日期或预算。
- 页面逐条说明冲突，并为每一条提供“去修改”。点击后打开详细设置、展开对应分组、滚动到具体控件并聚焦；所有冲突控件同时以红色标出。
- 页面同时提供“修改旅行描述”。点击后回到原始输入框并聚焦，用户自行删改原文。
- 修改任意一侧后，旧理解立即过期；用户必须再次点击“整理我的需求”并重新确认。

## 3. 面向用户的称呼与标签

产品名 `Melbourne TripAgent` 保留，但界面中的交互角色统一使用第一人称“我”，不反复自称 Agent。

理解来源统一为：

| 数据来源 | 页面文案 |
|---|---|
| 从自然语言识别 | 描述中提到 |
| 用户在设置中选择 | 详细设置 |
| 当前系统假设 | 暂用默认 |
| 缺少必要信息 | 需要补充 |

其他文案遵循游客视角：使用“详细设置”“同行人和预算”“公共交通最多预留”“和预算相比”“景点门票”等表达，避免“硬约束”“计价旅客”“预算判断”等实现术语。

## 4. 不变边界

- 仍使用本地规则理解需求，不声称已经调用真实 LLM。
- 仍由确定性规划器处理地点、时间、预算和约束。
- 保留“先理解、再确认、后生成”；失败时保留上一份成功行程。
- 保留全量候选审计、确认后替换和最多 20 步撤销。
- 不新增未经核验的外部图片，不发布到线上。

## 5. 验收点

1. 行程中每个地点都有照片或清楚标注的地点示意。
2. 可选与暂不可选的替代地点均有视觉素材。
3. 描述与设置产生多项冲突时，每一项都能跳到对应控件。
4. 修改后旧冲突提示不会继续冒充当前状态。
5. 页面除产品名外不再用 Agent 称呼交互角色。
6. 类型检查、静态检查、自动测试、数据校验、生产构建和静态发布包校验全部通过。
